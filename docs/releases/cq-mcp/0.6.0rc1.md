# 0.6.0rc1 预发布说明

状态：已于2026-10-26公开预发布至[PyPI](https://pypi.org/project/ai-code-quality/0.6.0rc1/)
和[GitHub Releases](https://github.com/lkdx0220/ai-code-quality-skill/releases/tag/v0.6.0rc1)。
两平台公开安装复验完成，详细证据见[发布记录](../../../openspec/changes/archive/2026-10-26-add-local-cq-mcp/publication-0.6.0rc1.md)。
这是rc预发布版，尚未发布0.6.0稳定版。
旧v0.5.2不含MCP，使用新版本号避免把不同内容混装为同一个0.5.2包。

## 变化

- 同一发行包保留CLI/Skill入口，增加本地stdio MCP的九个工具，复用cq核心。
- 异步doctor/scan、持久化幂等job、取消和总期限；Windows Job Object及Linux进程组管理。
- 完成标记、输入监视摘要、历史/当前证据判定、finding分页、不可变快照与分块读取。
- SQLite竞争、空间耗尽、服务崩溃的保守恢复；gate/diff遗留预留在安全条件满足后回收。
- 修正POSIX虚拟环境解释器被解引用到基础Python而看不到已装工具的问题，覆盖四种配置来源。
- 所有检测依然来自外部开源分析器，MCP不提供源码修改、依赖安装或Git写入工具。

## 兼容变化

旧CLI正常参数继续适用；显式空adapter列表/空字符串改为拒绝，避免意外回退全量执行。
run目录碰撞改为报错，避免原目录合并覆盖。证据JSON增加字段及完成标记；
旧run可以按明确的unknown策略展示，不能把缺少证据的历史结果作为当前质量通过。
不同cq版本的run可展示差量，但不承诺可比；升级后应重新生成需要作可信比较的双方run。

## 安装

推荐在独立虚拟环境从PyPI安装：

```bash
python -m pip install "ai-code-quality[mcp]==0.6.0rc1"
```

Python≥3.11。应在全新虚拟环境安装本次核验的wheel或sdist，避免覆盖现用环境：

```text
python -m venv /absolute/cq-rc-env
/absolute/cq-rc-env/bin/python -m pip install "/absolute/packages/ai_code_quality-0.6.0rc1-py3-none-any.whl[mcp]"
/absolute/cq-rc-env/bin/python -m ai_code_quality.mcp --project /absolute/trusted-project --state-dir /absolute/cq-rc-state --tool-python /absolute/tool-python
```

Windows将解释器改为`C:/path/cq-rc-env/Scripts/python.exe`。服务和分析器解释器分开，
不要求把分析器安装进服务环境。依赖元数据固定MCP2.3.0及Windows的pywin32312；
传递依赖按实际平台解析，预检记录中的constraints只描述该次样本，不能跨平台当通用锁文件。
核心CLI不选extra时仍无运行时依赖。

许可证见[第三方声明](../../third-party.md)：cq为MIT，但pywin32含多个组件许可，
包括adodbapi的LGPL-2.1-or-later。候选wheel/sdist只含cq自身文件及通知，不捆绑第三方环境。
