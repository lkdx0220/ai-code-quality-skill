## 一、发现（按 P0/P1/P2/P3）

### P2-1 design §6.10「所有输出经版本化规则」与 md 控制台实现不符：`cq scan` 默认格式的成功 stdout 不脱敏

- 源码：`src/ai_code_quality/report.py:183-205`（`build_console_output` 无任何 redact 调用，`tools[].reason` 原样进入输出）；`src/ai_code_quality/cli.py:814-815`（`_print_scan_console` 直接打印）；对照 `cli.py:810-813`（`--format json` 路径已加 `redact_obj`）。
- 触发输入（已实测，探针 D，`adversarial/probes_detail.txt`）：构造 adapter 返回 `reason="probe Authorization: Bearer ghp_<36位程序化假token>"`（程序生成假凭据），`run_scan` 后调用 `build_console_output`。
- 预期：design §6.10 "所有输出经版本化规则，见§9"。实际：**md 控制台输出原样包含 token**；同一 run 的 `summary.json` 与 `report.md` 磁盘产物均正确脱敏（`REDACTED`）。`reason` 的现实来源包括 `adapters/base.py:64` 的 `safe_run` 异常路径（`adapter 内部异常: {exc}` 可嵌工具输出）。
- 影响：泄露面限于本地终端回显（不是持久产物）；MCP 服务固定以 `--format json` 调用核心（design §7），该通道已脱敏（实测）。风险在于契约措辞让"MCP 已脱敏"之外还存在一条未脱敏的成功输出通道，且与 r01 DS 报告"md 控制台已脱敏"的表述矛盾（该表述与实现不符，两轮均未实测此点）。
- 定级理由：pre-existing（r01 即如此，非本轮修订引入）、不在 MCP 消费路径、不落盘 → P2 而非更高。
- 最小修正方向：`build_console_output` 末尾整体过 `redact_text`（与 `build_report_md:26` 同构，一行级）；或修订 design §6.10 措辞为"所有落盘产物与 JSON 输出"。
- 进入服务层前是否必须修复：**否**（但服务层契约必须写死"仅消费 --format json"，且此项应在下批一并收口）。

### P3-1 `cq suppress --reapply` 对非 UTF-8 的 `.cq/suppressions.json` 裸 traceback；scan 中同类文件误标 INVALID_ARGUMENT/exit1

- 源码：`src/ai_code_quality/suppress.py:115-117`（`load` 仅捕 `OSError, json.JSONDecodeError`，不含 `UnicodeDecodeError`）；`cli.py:677-699`（`_run_suppress_command` 仅捕 `SuppressionError`）；`scan.py:195-199`（`_apply_suppressions` 经 `load`）。
- 触发输入（已实测）：`.cq/suppressions.json` 写入 `b"\xff\xfe[]"` 后运行 `suppress --reapply` → **exit1 + UnicodeDecodeError traceback**；运行 `scan --format json` → exit1、`{"error":{"code":"INVALID_ARGUMENT","message":"'utf-8' codec can't decode…"}}`（不崩溃但把项目文件损坏标成调用参数错误）。
- 影响：pre-existing（suppress.py 与该 CLI 路径本轮均未改），不在 r01 P2-1 的 marker/summary/findings 范畴（那六个消费者对 run 产物损坏已全部干净，见第二节）；MCP 不调用 suppress。scan 路径 fail-closed 方向正确（无 marker、后续读取 RUN_NOT_READY），仅错误码语义错位。
- 最小修正方向：`suppress.load` 的捕获元组补 `UnicodeDecodeError`；scan 侧将其映射为 INVALID_ARTIFACT/exit 3 或 4。
- 进入服务层前是否必须修复：否。

### P3-2 AMBIGUOUS_BASE_RUN 未实现：具名 baseline 与 run 同名时静默具名优先

- 源码：`src/ai_code_quality/baseline.py:47-49`（`path.is_file()` 即采用具名基线，无歧义检查）；cli.py 的 diff/gate 未检查同名 run。
- 触发输入（已实测，探针 A）：`cq baseline --run dup --name dup` 后 `cq diff --run dup --baseline dup` → exit 0，`baseline` 字段为 `"dup"`、`baseline_run` 为合成标记 `"dup(←dup)"`——具名文件静默胜出，design §7 要求的 `AMBIGUOUS_BASE_RUN` 不存在。
- 影响：非本批缺陷——`tasks.md` T13（CQ-MCP-10）已把"同名baseline拒绝"列为服务层任务；且此行为与我 r01 记录的"具名 baseline 优先=兼容保持"一致。风险仅在服务层实现 `cq_diff` 时若忘记前置检查，劫持是静默的。
- 最小修正方向：T13 实现时在服务层（或核心 load_baseline）检查"基线名同时命中具名文件与 run 目录"并报 AMBIGUOUS_BASE_RUN。
- 进入服务层前是否必须修复：否（属 T13 范围），但 T13 验收必须含此反例。

### P3-3 指向项目根外的 symlink **目录**被静默不监视（文件链接则 fail-closed，行为不对称且未文档化）

- 影响：监视集合本已声明"非分析器读取全集"（monitor_scope），但文件链接 fail-closed、目录链接静默跳过的**不对称**未在任何文档记录。

- 进入服务层前是否必须修复：否。

### P3-4 记录性观察（均不阻塞）

1. **短 token 非头形态不脱敏**（已实测）：`Bearer abc`（<8 字符）原样输出——`redact.py:24` 的 `{8,}` 下限是防行文误报的既定取舍（处置记录在案）；`Authorization:` 头形态则任意长度都脱敏（`redact.py:19`）。与"不承诺识别所有秘密"的披露一致。
2. **`raw/coverage.json` 按设计保留分析器原字节、其内文件名不经脱敏**（实测确认 CRLF 原样、marker 按原字节摘要）：若源文件名本身含凭据形态，该 raw 文件内为原名。design §9 已限定 MCP 只返回覆盖率汇总数值、不开放 raw artifact，泄露面限本地磁盘；与 inputs.json 的 v2 路径脱敏形成有意不对称（字节保真承诺优先），建议补一句文档。
3. **gate 保存路径二次 `load_run`**（`cli.py:650`）：冗余一轮全量摘要核验，纯性能，r01 P3-5 遗留，处置为 deferred，一致。
4. **findings 条目仅校验 dict 形状**（`runs.py:137-138`）：任意键的 dict 条目可载入（实测）。published run 有 marker 字节完整性兜底，legacy 宽容解析为既有设计；可接受。
5. **`cq.toml` 仅支持顶层键与 `[tool]` 表**：`[tool.cq] python=...` 被静默忽略（实测 python_source 仍 default）。旧语义未变，非本轮改动。
6. **`--inputs-timeout-seconds` 接受小数**（如 0.5）：核心校验 `0<x<=600`；design §2 的 1..600 由 MCP 启动参数收紧，核心略宽，无实质风险。
7. **候选文件行尾混合**：evidence/redact/runs/targets 为 LF，cli/config/scan 为 CRLF（原字节呈现，未归一化判断）；ruff format 57 文件通过，无功能影响。主仓工作区中 diff.py/suppress.py/doctor.py/.cq 相对 HEAD blob 也仅行尾差（内容级一致，difflib 复核），作者"不变项"声明成立。
8. **并发同 run-id 无自动化测试**（r01 DS 实测过 1 赢家+3 碰撞；`mkdir(exist_ok=False)` 结构上保证）；`after` 监视阶段单独失败、`check_deadline` 机制、Python 3.11 真机仍无直接测试/证据（与 r01 盲区清单相同的遗留）。
